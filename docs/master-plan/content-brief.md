# Portfolio content brief

Revised 13 October 2026 following the SWEBOK review, Docker/Cloudflare decision and Git/GitHub source publication request. This records owner inputs; it does not imply that suggested defaults or content quantities are already approved.

Confirmed direction: a personal home for projects and writing, retaining Navfolio’s overall visual style, with English and Bahasa Indonesia support. Use Git version control, publish source on GitHub, run locally in Docker and host on Cloudflare Workers Free; the [hosting assessment](./docker-cloudflare-hosting.md) explains the proposed static publishing workflow.

Complete the information you want to publish. No credentials, private contact details, or unpublished client information are needed.

## About

Write a short biography covering what interests you, what you work on, why you publish, and how readers can contact you. Supply the original in whichever language is easier; any translation should be reviewed for accuracy and voice before publication.

Avoid generic skill lists unless they help explain actual work. A few concrete interests and examples will fit this site better than a long résumé-style introduction.

## Each project

- Title, short description, and current status.
- The problem and intended audience.
- Your role and contribution, including collaborators where relevant.
- Technologies and the reasons for important choices.
- Two or three useful screenshots or diagrams, with captions.
- Results or evidence that can be substantiated.
- Lessons learned and possible next steps.
- Public repository, live demo, documentation, or related article links.
- Original language and whether a reviewed translation exists.

Suggested first release: two substantive projects. Real work in progress is suitable when its status is clear.

## Each article

- Working title, one-sentence description, original language, and publication date.
- Full text or an outline.
- A small set of topics/tags and an optional series.
- Images or code samples, with sources/permissions where needed.
- Draft or ready-to-publish status.
- Translation pairing, if a second version exists.

Suggested first release: three useful pieces. They can include project write-ups, technical explanations, or thoughtful progress notes. Each piece can exist in only one language.

## Homepage

- A brief introduction, ideally two or three sentences.
- Three current interests or activities.
- Which two projects should be featured.
- Which article should be pinned, if any.
- Whether you want to show writing activity statistics from the beginning.

## Proposed defaults

Keep the green-soft palette and Maple Mono visual character. Launch with Home, Writing, Projects, and About. Enable search, light/dark themes, language selection, and RSS. Defer comments, Media, short-form Notes, analytics, and a newsletter. These defaults can be revised without changing the core goal.

## Publication review

For each asset, record its source/creator, permission or license basis, and required attribution. For each project, distinguish your contribution from collaborators' work and distinguish measured results from expectations. Do not include confidential client material. Both language versions should preserve meaning; translation availability can differ by entry.

If an article exists only in English or only in Indonesian, publish it honestly in that language. A localized empty archive is acceptable. Never produce a duplicate placeholder translation to satisfy a content count.

Proposed future-date behavior: entries become eligible when the site's recorded build date reaches their calendar date in Asia/Jakarta; a new build is needed. Automatic scheduling is deferred. A draft excluded from the site can still be visible in a public source repository, so private drafts must stay outside the planned public repository. Resolve the GitHub destination and source-publication boundary before the first push.

The acceptance rehearsal is practical: find and read a piece, inspect a project, switch an actual translation, understand an original-only entry, then add/correct a publication using the guide. Record any confusing step so the workflow can be improved before handover.
